Leaf context menu, Phase 1. `ContextMenuHost` replaces the browser's right-click menu in one document (mount one per document, including a Document Picture-in-Picture window) and renders nothing, with no listeners, while the shell's `configureContextMenu({ enabled })` is off, which is the default. The browser's menu stays for inputs, textareas and contenteditable, for events another handler already prevented (Monaco, Base UI context-menu triggers), for Shift+right-click and under `data-context-menu="native"`; `data-context-menu="none"` and a right-drag past 5 px show neither. The menu is the innermost registered object, then selection (Copy), link (Open, Open in new tab, Copy link; internal links route through the host's `navigate`), image, video or audio (Open, Save, Copy image in a secure context, Copy address), then a Back, Forward, Reload and Copy page link icon row and the command palette. On touch, a 500 ms long-press over an object, link or media opens the same items in a bottom sheet. Item descriptors (`ContextMenuItem`, with an optional `commandId` that borrows a palette command's label, shortcut and action) render through `ActionMenuItems` and the shared `RowActionsMenu` ⋮ trigger, so a row's ⋮ menu and its right-click menu are one array. `useContextTarget(ref, getItems)` registers an element (a no-op while off) and renders its menu in the registering component's portal container, so a plugin's scoped CSS applies. `registerContextMenuProvider` adds kind providers: an owner `match`es elements, a contributor adds a capped group to a kind it does not own, and `getDeferredItems` appends permission-checked items without delaying the rest. `DropdownMenuContent` accepts `anchor` and `collisionPadding`, and `DropdownMenuSub` now uses Base UI's `SubmenuRoot`, without which a submenu trigger threw. `LeafAppPlugin.contextMenu` (optional) lets a plugin contribute providers.
